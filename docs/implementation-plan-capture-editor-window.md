## 2. 実装する操作仕様

### 2.1 「常に最前面」チェック

- メイン画面のヘッダーへチェックボックス「常に最前面」を追加する。
- 初期値OFF。変更を既存設定ストアへ保存し、次回起動時に復元する。
- ON/OFFを即時反映。プレビュー・編集・テキスト入力ダイアログが親画面の裏へ隠れないように所有関係を維持する。
- アプリ独自キャプチャ中は現行どおりアプリを隠し、完了・キャンセルで状態を復元する。
- 最小ウィンドウ幅、100/125/150/200% DPIでラベルの折返し・見切れ・スクロールバーが発生しない配置にする。

### 2.2 テキストの直接移動・再編集・削除

- 「移動」ボタンと専用ツールの分岐を廃止し、既存テキスト上のドラッグで直接移動する。
- マウス操作の優先順位は「×ボタン → テキスト → 選択中の描画ツール」。テキスト以外では枠・矢印等の既存操作を続ける。
- クリックで選択、ダブルクリックで文字列を再編集する。既存テキストを入力済みのダイアログを開き、確定で同じIDの注釈を更新する。位置と色を維持し、文字数変更後に境界を再計算する。
- 選択したテキストの右上に×ボタンを表示し、押すとその注釈を削除する。空文字確定は削除扱いにせず、入力を促す。
- ×は画像の縮小率とは独立した押しやすい表示サイズとし、画面端でも押せる場所に収める。×や選択枠は出力画像に含めない。
- 移動開始にはドラッグ距離の閾値を設け、クリック・ダブルクリック・削除が移動操作にならないようにする。移動中はプレビューだけ更新し、ドロップで1操作として履歴へ記録する。
- 移動・編集・削除を既存Undo/Redoの対象とする。ドラッグ中のEscやマウスキャプチャ喪失では未確定の移動を取り消す。
- 重なったテキストは手前の注釈を選択。スクリーンショットに元から写っている文字の編集や、確定してExcelに配置した画像の注釈再構成は対象外。

関連して、現行のCropは全注釈を画像へ合成し、Mosaicも合成した画像を編集するため、その後のテキスト操作ができなくなる。この点も実装時に処理する。Crop後は残った注釈の座標・表示範囲を変換し、Mosaicとの併用では注釈の編集状態とモザイクの適用順を保持する。移動・再編集・削除によって隠した画素が露出しないことを受入条件とする。単に注釈を最前面へ描き直す変更はしない。

### 2.3 配置後の対象Excelの前景化

- 画像配置の検証が成功し、必要な末尾行整理と次の配置先設定が完了した後、今回配置した対象ブック・シートを表示して前景化する。
- アプリ上の次のCASE/Sideと、Excelに表示する今回の配置場所を区別する。Excelへのフォーカス移動による選択イベントで、次の配置先設定が元へ戻らないようにする。
- 対象を既存のWorkbookIdentityとウィンドウ情報で検証し、複数Excelプロセス・複数ブックから正しいウィンドウへ切り替える。最小化中なら復元する。
- 既存の「配置位置より3行上から表示、A列を表示」を維持する。
- メイン画面のfinally等による再Activateで、Excelからフォーカスを奪い返さないよう完了結果を伝える。キャンセル時はアプリへ戻す。
- 本計画での共存仕様: 最前面モードOFFならExcelがアプリの手前になる。ONならアプリは手前に残し、キーボード操作先はExcelへ渡す。Excelそのものを常時TopMostにはしない。
- OSが前景化を拒否した場合は「配置済み／前面表示できず」を分けて扱う。配置を再試行して画像を二重に追加しない。

WinFormsのTopMostは表示順の指定であり、操作フォーカスとは別である。[Microsoft公式: Form.TopMost](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.form.topmost?view=windowsdesktop-9.0)

Windowsには前景化の制限があるため、成功を戻り値等で確認する。[Microsoft公式: SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)

### 2.4 Win+Shift+Sでのプレビュー二重表示

1. Clipboard通知の時刻・シーケンス番号・受付/解析/プレビュー/編集/配置の状態を記録し、二重表示が同時か連続かを特定する。画像内容はログへ保存しない。
2. 最初のawait以前に受付状態を確保し、解析からプレビュー、編集、配置またはキャンセルの終了まで1件だけ処理する。
3. QueueClipboardPreview、再試行タイマー、独自キャプチャ、画像書き出し時のClipboard退避・復元を確認し、同じ画像受付制御に整合させる。
4. 処理中の通知は集約する。終了時に処理済みの更新と新しい画像を区別し、新しい画像の受付を再開する。
5. 異なるシーケンス番号で同一キャプチャが再通知される場合だけ、取得元・通知間隔・画像同一性を使った限定的な重複除外を検討する。同一内容を後から再撮影する操作を恒久的に除外しない。
6. Clipboardロック、キャンセル、例外のどの経路でも受付状態・画像リソース・一時ファイルを解放する。

同時プレビュー数が1であることに加え、1回の撮影からプレビューを閉じた後に同じものが再出現しないことを確認する。短時間に別の撮影を行った場合は、現在の処理後に最新の未処理画像を扱う方針とし、無制限の画像キューは追加しない。

### 2.5 Enter操作

| 画面 | キー | 動作 |
| --- | --- | --- |
| メイン | Enter | 画面キャプチャ開始 |
| プレビュー | Enter | 編集せず配置 |
| プレビュー | Shift+Enter | 画像編集画面へ進む |
| 画像編集 | Enter | 編集内容を確定して配置 |

- 同じ画面内で別のボタンへフォーカスがあっても、表のショートカットを優先する。
- 入力中の日本語IME確定、開いているComboBoxの候補確定、子ダイアログ内の操作はその入力先で処理する。
- テキスト入力ダイアログ内のEnterは改行とし、画像配置へ伝播させない。子ダイアログを確定後、編集画面でEnterを押すと配置する。
- メイン画面のSheet/CASE欄の入力はキャプチャ開始前に検証・確定する。IME確定のEnterではキャプチャしない。
- 処理中・配置不可状態では確定しない。キー長押しや連打で次の画面まで連続確定しないようにする。
- 未指定のShift+Enter（メイン・編集）は新たな配置ショートカットとして追加しない。
- 既存のCtrl+Z/Ctrl+Y、Esc、キャプチャ用ホットキーを維持する。

### 2.6 画像配置済みCASEへの追加

- 明示的に選んだCASE/Sideへの追加配置を認め、自動進行時の「配置済みをスキップ」と混同しない。
- 同じSideの既存画像等の末尾から最低2行空けて追加する。初回の配置オフセットは現行の1列右・2行下を維持する。
- 管理画像だけでなく、手動貼り付け画像、移動・サイズ変更済み画像、両SideやCASE境界をまたぐ画像も占有情報に反映する。
- 現行のスナップショット、ContentOccupancyAnalyzer、PlacementPlanner、配置時の再検証を追い、取りこぼしや古い情報の再利用が再現した部分を修正する。
- 空き高さが不足する場合は既存の行挿入・補償処理を利用する。正しく判定できない場合は重ねて貼らず理由を表示する。
- 実Excelではセル番地の判定に加えて、配置後の画像矩形（Left/Top/Width/Height）の交差で非重複を検証する。
- NEW/OLDが揃った後の余白整理を含めて、既存画像・追加画像・次CASEのコンテンツが損なわれないことを確認する。
- この要件では新しい全面走査や常時ポーリングを追加しない。必要な対象範囲を読み、既存性能改善を維持する。

## 4. 検証と受入基準

### 自動テスト

- テキストの移動・文字列変更・削除についてID、位置、色、境界、Undo/Redoを検証する。
- Crop/Mosaic併用時の座標と出力画素を検証し、モザイク対象が露出しないことを確かめる。
- 受付制御は重複通知、解析中/編集中の通知、Clipboard再試行、キャンセル、例外、同一内容の別撮影を対象とする。
- 既存のPlacementPlannerTests、ContentOccupancyAnalyzerTests、AutomaticPlacementServiceTestsへ、再現条件を追加する。
- 配置失敗時に前景化しないこと、前景化だけ失敗しても配置成功として扱うことを確認する。

### 実機確認

- Win+Shift+Sを単発・連続で行い、解析中・プレビュー中・編集中・配置中それぞれの通知について、二重表示も二重配置もないことを確認する。
- アプリ独自キャプチャとWindowsキャプチャの両経路で、Enter/Shift+Enter、長押し、IME変換、入力ダイアログ、キャンセルを確認する。
- 最前面ON/OFF × Excel通常/最小化 × 複数ブック/複数プロセスで、今回の配置先が表示されることとアプリの次の配置先が維持されることを確認する。
- 最小/通常ウィンドウサイズ、100/125/150/200% DPI、複数モニターでチェック表示・ドラッグ・×・テキスト再編集を確認する。
- 参照ブックは一時コピー上で検証する。NEWのみ、NEW/OLD、罫線なし、既存画像1枚/複数枚、管理外画像、画像移動/拡大後、行高混在、非表示行、末尾CASE、余白整理後を対象とする。
- プレビュー表示中にExcel画像を変更した場合は、古い配置計画で衝突させず再解析または安全停止することを確認する。
- 追加配置の前後で既存画像矩形、CASE番号、行構造、書式、補償処理を確認する。

### 性能と完了条件

- 同じ一時ブック・同じ画像で、解析開始→プレビュー表示、確定→配置/次の配置先決定までを変更前後で各5回以上測定し、初回とウォーム実行を分けて中央値を比較する。
- 重複解析回数も測り、受付制御によって不要なExcelアクセスが抑えられていることを確認する。
- SDK 9.0.304でbuild、関連テスト、必要なExcel結合テスト、publishを行う。
- 最終差分レビューと上記の受入検証後、実装済み・未検証・環境制限を区別して報告する。今回の成果物は本計画書のみ。
