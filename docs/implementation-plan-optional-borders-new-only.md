# 罫線任意・Newのみ対応 実装計画

## 1. 目的

EvidenceCrafterのCase解析を、実際の雛形作成・運用に合わせる。

- Case番号は必須とし、Case認識の主信号にする。
- 罫線は任意とし、Case認識・画像配置の必須条件から外す。
- Side構成は `NewOnly` または `Both`（New/Old）とする。`OldOnly` は扱わない。
- 現行の画像配置位置、画像サイズ、2行マージン、安全確認、Undo/Redo、
  自動保存しない動作を維持する。
- 罫線が存在する場合は、構造確認と異常検出の補助信号として利用する。

## 2. 現状との差分

現行実装では、先頭以外のCase番号行を上罫線で確定し、New/Oldの境界を縦罫線で確定する。
また、最終Caseの終端には下罫線または縦罫線の終端を要求する。
そのため、Case番号が正しく配置されていても罫線のない雛形は解析できない。

Sideについても `EvidenceCaseLayout` がNew領域とOld領域の両方を必須としており、
Case移動は全CaseにNew/Oldの2ブロックが存在するとみなしている。

## 3. 雛形との契約

### 3.1 Case番号

- A列を親番号、B列を子番号として扱う。
- A列が空でB列に子番号がある場合は、直前の確定Caseの親番号を継承する。
- 正規化後に `X-X` を作れる行だけをCase Anchorとする。
- 同一シート内の同じ `X-X` は曖昧なため、該当行を表示して安全停止する。
- 上罫線の有無はAnchor採否に使用しない。

Case番号以外のA/B列文字列をAnchorとして誤認しないよう、番号の構文検証をSnapshot取得後の
共通正規化処理へ集約する。

### 3.2 Side構成

参照ブックではEvidenceシートの2行目に「新」「旧」があるため、シート単位で次のように判定する。

| ヘッダー | 構成 | 配置可能Side |
|---|---|---|
| 「新」あり、「旧」なし | `NewOnly` | New |
| 「新」「旧」あり | `Both` | New、Old |
| 「新」なし、または「旧」だけ | 判定不能 | 配置しない |

- 「旧」の列をOld開始列、その1列前をNew右端とする。
- `NewOnly` はC列からEvidence最終列までをNew領域とする。
- 縦罫線がある場合は、ヘッダーから求めた境界との一致を確認する。
- 罫線だけがありヘッダーがない場合は、運用契約を満たさないため安全停止する。

この契約は、1枚のシート内で全Caseが同じSide構成である場合に適用できる。
同じシート内に `NewOnly` と `Both` が混在し、見た目の列構成が同じ場合、空のOld領域だけでは
「未配置」と「不要」を区別できない。その運用がある場合は、雛形生成時にCaseごとの明示マーカーを
追加し、その値をSnapshotへ取り込む第2段階を実施する。マーカーのない状態で推測はしない。

### 3.3 Case終端

- 次のCase Anchorがある場合は、従来どおり `次Anchor行 - 1` を終端とする。
- 最終Caseは、Evidence列内のUsedRange終端を基本終端とする。
- 下罫線または縦罫線終端がある場合は、基本終端との整合を確認する補助信号にする。
- 罫線とCase番号由来の範囲が矛盾しても、Case番号と実コンテンツが範囲内なら配置は継続し、
  診断へ警告を記録する。
- Evidence範囲より下に別用途の表や注記があり、最終Case終端を一意に分離できない場合は、
  最終Caseへの行削除を停止する。画像配置は既存内容と重ならない位置へ限定する。

## 4. データモデル変更

1. `EvidenceCaseLayout` のOld領域を任意にし、`SideLayoutKind`（`NewOnly` / `Both`）を追加する。
2. `SheetLayoutSignals` にヘッダーから取得したNew開始・Old開始・Evidence最終列と、
   罫線警告を保持する。
3. `CaseAnchorSignal` は罫線確認済みかどうかを診断情報として残すが、確定条件にはしない。
4. 配置要求のSideがレイアウトで利用できるかを共通メソッドで検証する。

Old領域を空のダミー範囲で表現しない。存在しないSideを型で表現し、幅計算や占有判定が
誤ってOldへ進まないようにする。

## 5. 実装手順

### Phase 1: Case AnchorをCase番号基準へ変更

- `ExcelSheetSnapshotService.ReadAnchors` はA/Bの値と罫線状態を取得する。
- `ExcelAutomaticPlacementService.ConfirmedAnchors` をCase番号構文中心に変更する。
- `CaseLayoutAnalyzer` から、先頭以外の上罫線必須条件と次Anchorの上罫線必須条件を外す。
- Case検索、手入力、前後移動、配置解析で同じAnchor一覧を再利用する。

### Phase 2: Side構成をモデル化

- シートヘッダーから `NewOnly` / `Both` を解析する。
- `CaseLayoutAnalyzer.ResolveSideBoundary` を、Side構成を返す処理へ置き換える。
- `NewOnly` ではOld選択を拒否し、画面上のOldを無効化してNewを選択する。
- Workbook選択、Sheet変更、Case移動でSideの利用可否を再評価する。

### Phase 3: 配置・遷移・完了処理を対応

- Newは全レイアウトで配置可能にする。
- `NewOnly` へのNew配置後は、同じCaseのOldを候補にせず次CaseのNewへ進む。
- 前／次Case移動と空き検索は、各レイアウトが持つSideだけを列挙する。
- `Both` のみ、New/Old双方の画像がそろった時点で末尾2行を残す整理を実行する。
- `NewOnly` は片側完成として扱うが、自動行削除は実行しない。
- Undo/Redo履歴には実際に利用したSide構成を保持し、再解析時に構成が変わっていたら安全停止する。

### Phase 4: 罫線を補助信号へ変更

- 罫線取得を配置可否の必須経路から外す。
- 存在する罫線はヘッダー境界・Case番号範囲との矛盾検出に使う。
- 罫線がない通常ケースを警告扱いにしない。
- 罫線取得を必要な範囲に限定し、罫線なしシートで不要なセル単位走査を行わない。

### Phase 5: UIとメッセージ

- 配置予定表示に `構成: Newのみ` または `構成: New/Old` を追加する。
- `NewOnly` ではOldボタンを無効化し、ToolTipで「このシートはNewのみ」と表示する。
- 罫線の欠落をエラー文から除き、Case番号・ヘッダー・最終Case終端の具体的な不足を表示する。
- SheetまたはCaseをユーザーが変更した場合も同じ再判定を適用する。

## 6. テスト計画

### Coreテスト

- 上罫線なしで複数の `X-X` Anchorを認識する。
- A列継承、全角ハイフン、重複Case、Case形式でないA/B文字列を検証する。
- 次Anchorによる可変Case間隔（30行、50行、不均一）を検証する。
- `NewOnly` と `Both` の領域、利用可能Side、幅計算を検証する。
- 罫線あり／なしで同じCase・Side・開始セル・配置寸法になることを比較する。

### Excel結合テスト

参照ブックは変更せず、OS一時フォルダに次の試験ブックを生成する。

1. 複数Case・New/Old・罫線あり。
2. 複数Case・New/Old・罫線なし。
3. 複数Case・Newのみ・罫線あり。
4. 複数Case・Newのみ・罫線なし。
5. Case間隔が不均一な最終Case。
6. 幅の異なる列、既存画像、セル文字、管理外Shapeを含むCase。

各ブックで自動判定、プレビュー、画像配置、前後移動、自動遷移、行挿入、Undo/Redoを確認する。
`NewOnly` でOldへ進まないこと、両Side完成整理が実行されないことを確認する。
罫線あり版となし版では、配置先と画像寸法が一致することを確認する。

### 参照ブック確認

- 個別EvidenceのB1/B2/B3、および共通EvidenceのA1を読み取り専用で解析する。
- 変更前後で参照ファイルのSHA-256が一致することを確認する。
- 既存のNew/Oldシートの配置結果が現行版と一致することを確認する。
- 実運用のNewのみブックを1件、受入試験へ追加する。

## 7. 性能条件

- Case番号とヘッダーはUsedRangeの値・数式配列から解析し、セルごとのCOM呼び出しを増やさない。
- 罫線なしと確定した経路では連続罫線の終端走査を省略する。
- Sheet選択監視では、値・ヘッダー・Shape一覧が変わらない限り既存Snapshotを再利用する。
- 現行版と同じ実Excel条件で、Workbook選択、Case移動、配置後遷移を計測する。
- 各操作が現行版より遅くならず、罫線なしシートでは罫線走査時間を発生させないことを受入条件とする。

## 8. 安全条件

- ReadOnly、保護Sheet、切断、Case番号重複、Side構成不明では書き込まない。
- Snapshot fingerprintと書き込み直前の状態が異なる場合は中止する。
- 管理外Shape、値、数式、コメント、リンクを占有物として維持する。
- 最終Case終端が不明な場合、行削除は行わない。
- Workbookは自動保存しない。
- Case&Evidenceの参照ファイルを直接編集しない。

## 9. 完了条件

- 罫線なしでもCase番号とSideヘッダーから配置先を解析できる。
- NewのみのシートでOldを提示・選択・遷移しない。
- New/Oldシートの既存動作と配置結果を維持する。
- Case移動・配置後遷移が存在するSideだけを対象にする。
- 通常テスト、追加Coreテスト、実Excel結合テスト、参照ハッシュ確認、Release buildが成功する。
- 単一EXEを発行し、レビュー資料と受入確認リストを更新する。

## 10. 実装前に確定する一点

同じEvidenceシート内で `NewOnly` と `Both` が混在する運用があるかを確認する。
混在しない場合は本計画のシートヘッダー判定で実装できる。
混在する場合は、雛形生成側にCaseごとのSide構成を示す安定したマーカーを追加してから実装する。
