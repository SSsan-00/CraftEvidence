# CASE境界への画像侵入の修正

対象: 0.1.0-preview.29 / .NET SDK 9.0.304

## 再現条件と原因

画像は配置先セルの上端から2ポイント下げて挿入される。一方、従来の自動配置計画は画像の高さだけで必要行数を計算していた。

たとえば行高15ポイントの行へ高さ30ポイントの画像を配置する場合、計画上は2行で収まるが、実画像は2ポイント下から開始するため3行目へ到達する。このずれがCASE末尾付近で起きると、画像が次CASEの領域まで達し得る。

## 修正

配置セルの縦余白2ポイントを、画像の必要行数、末尾余白、および行追加の計算に含めた。実際のExcelへの配置も同じ共有定数を使用する。

参照ブックのコピーで、1-1 NEW → 1-2 NEW → 1-2 OLD → 1-1 OLDの後戻り配置を実行し、各画像の開始・終了行が対応CASEの開始行と次CASE番号の間に収まることを検証する。既存セル、画像同士の重なり、および参照元のSHA-256不変も確認する。

検証結果: `AppendImages_InReferenceCopies_DoNotOverlap` が成功（1分59秒）。結果ファイルは `artifacts/test-results/case-boundary-preview29.trx`。
